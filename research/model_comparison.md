# Задание 1. Исследование моделей и инфраструктуры

## 1. Сравнение LLM

| Критерий | GPT-4o-mini (OpenAI) | Llama 3.1 8B (локальная) | YandexGPT Lite |
|---|---|---|---|
| **Качество ответов** | Высокое. Отличное следование инструкциям, поддержка few-shot и CoT | Среднее. Хорошо для простых задач, слабее на сложных рассуждениях | Среднее. Хорошо для русского языка, слабее на английском |
| **Скорость (tokens/sec)** | ~100-150 t/s (облако) | ~20-40 t/s (GPU RTX 3060) | ~80-120 t/s (облако) |
| **Стоимость** | $0.15/1M input, $0.60/1M output | Бесплатно (но нужен GPU ≥8GB VRAM) | ~0.20₽/1K токенов |
| **Контекстное окно** | 128K токенов | 128K токенов | 8K токенов |
| **Развёртывание** | API-ключ, без инфраструктуры | Требуется GPU-сервер, VRAM ≥8GB, установка Ollama/vLLM | API-ключ, без инфраструктуры |
| **Мультиязычность** | Отлично (en, ru, и др.) | Хорошо (en), средне (ru) | Отлично (ru), средне (en) |
| **Поддержка RAG** | Нативная через LangChain, OpenAI API | Через LangChain + Ollama | Через LangChain + YandexCloud SDK |

### Вывод по LLM
Для кейса QuantumForge Software (корпоративная база знаний, ~18K документов, русскоязычный интерфейс с возможностью масштабирования) оптимальный выбор — **GPT-4o-mini**:
- Лучший баланс цена/качество
- Не требует GPU-инфраструктуры
- Большое контекстное окно (128K) позволяет передавать больше чанков
- Отличная поддержка few-shot prompting и Chain-of-Thought

## 2. Сравнение моделей эмбеддингов

| Критерий | OpenAI text-embedding-3-small | all-MiniLM-L6-v2 (Sentence-Transformers) |
|---|---|---|
| **Размерность вектора** | 1536 | 384 |
| **Качество поиска (MTEB)** | 62.3% avg | 58.8% avg |
| **Скорость индексации** | ~1000 doc/min (API, зависит от сети) | ~5000 doc/min (локально, CPU) |
| **Стоимость** | $0.02/1M токенов | Бесплатно |
| **Развёртывание** | API-вызов | Локально, ~100MB модель |
| **Макс. длина входа** | 8191 токенов | 512 токенов |
| **Мультиязычность** | Хорошо | Средне (обучена на en) |

### Вывод по эмбеддингам
Для проекта рекомендуется **OpenAI text-embedding-3-small**:
- Единая экосистема с LLM (один API-ключ)
- Более высокое качество поиска
- Большая максимальная длина входа (важно для длинных чанков)
- Стоимость минимальна для объёма ~18K документов (~$0.50 на полную индексацию)

Для сравнения в рамках задания можно также протестировать `all-MiniLM-L6-v2` — она бесплатна и работает локально, что удобно для разработки.

## 3. Сравнение векторных баз данных

| Критерий | FAISS | ChromaDB |
|---|---|---|
| **Тип** | Библиотека (in-process) | Клиент-серверная БД |
| **Скорость поиска** | Очень высокая (~1ms на 100K векторов) | Высокая (~5ms на 100K векторов) |
| **Сложность интеграции** | Средняя (нужно управлять метаданными вручную) | Низкая (встроенное хранение метаданных) |
| **Фильтрация по метаданным** | Нет (нужна ручная реализация) | Да, встроенная |
| **Персистентность** | Ручное сохранение/загрузка | Автоматическая |
| **Масштабируемость** | До миллиардов векторов | До миллионов векторов |
| **Стоимость** | Бесплатно (MIT) | Бесплатно (Apache 2.0) |
| **GPU-ускорение** | Да (faiss-gpu) | Нет |
| **RAM** | Низкое потребление | Среднее потребление |

### Вывод по векторным БД
Для проекта QuantumForge рекомендуется **FAISS**:
- Максимальная скорость поиска
- Минимальное потребление ресурсов
- Достаточен для масштаба проекта (~18K документов)
- Проверен в production (Meta, Pinterest, Spotify)
- Простая интеграция через LangChain

## 4. Рекомендуемые конфигурации сервера

### Вариант 1: Облачный минимальный (рекомендуемый)
- **CPU:** 2 vCPU
- **RAM:** 4 GB
- **Диск:** 20 GB SSD
- **GPU:** Не требуется
- **Стоимость:** ~$10-20/мес (VPS)
- **Компоненты:** GPT-4o-mini (API) + OpenAI Embeddings (API) + FAISS
- **Подходит для:** До 50K документов, до 100 пользователей

### Вариант 2: Облачный средний
- **CPU:** 4 vCPU
- **RAM:** 8 GB
- **Диск:** 50 GB SSD
- **GPU:** Не требуется
- **Стоимость:** ~$30-50/мес (VPS) + ~$50/мес (OpenAI API)
- **Компоненты:** GPT-4o-mini (API) + OpenAI Embeddings (API) + FAISS + PostgreSQL (для логов)
- **Подходит для:** До 200K документов, до 500 пользователей

### Вариант 3: Гибридный (локальная LLM)
- **CPU:** 8 vCPU
- **RAM:** 32 GB
- **Диск:** 100 GB SSD
- **GPU:** NVIDIA RTX 3060 (12GB VRAM) или T4
- **Стоимость:** ~$100-200/мес (GPU-сервер)
- **Компоненты:** Llama 3.1 8B (локально) + all-MiniLM-L6-v2 (локально) + FAISS
- **Подходит для:** Полная автономность, конфиденциальные данные

### Вариант 4: Enterprise
- **CPU:** 16 vCPU
- **RAM:** 64 GB
- **Диск:** 500 GB SSD
- **GPU:** NVIDIA A100 (80GB)
- **Стоимость:** ~$500-1000/мес
- **Компоненты:** Llama 3.1 70B (локально) + BGE-large (локально) + Milvus
- **Подходит для:** Миллионы документов, строгие требования к безопасности данных

## 5. Итоговая рекомендация

### Выбранная конфигурация для QuantumForge Software

| Компонент | Решение | Обоснование |
|---|---|---|
| **LLM** | OpenAI GPT-4o-mini | Лучший баланс цена/качество, 128K контекст, не нужен GPU |
| **Эмбеддинги** | OpenAI text-embedding-3-small | Единая экосистема, высокое качество, низкая цена |
| **Векторная БД** | FAISS | Максимальная скорость, простота, бесплатность |
| **Сервер** | Вариант 1 (облачный минимальный) | Достаточен для ~18K документов, масштабируется |

### Аргументация
1. **Стоимость:** ~$10-20/мес за VPS + ~$5-10/мес за OpenAI API = ~$15-30/мес — минимальная для enterprise-решения
2. **Скорость развёртывания:** Полное развёртывание за 1 день (нет необходимости настраивать GPU, загружать модели)
3. **Качество:** GPT-4o-mini + text-embedding-3-small обеспечивают высокое качество ответов и поиска
4. **Масштабируемость:** При росте до 200K+ документов — переход на Вариант 2 без изменения кода
5. **Надёжность:** OpenAI API имеет SLA 99.9%, FAISS — проверенная библиотека от Meta
